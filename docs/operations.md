# 本地运行说明

先运行单元测试，再执行演示命令。演示从干净临时目录发起真实请求并处理响应，不需要外部站点。
常规导入失败时返回非零退出码，事务中的原文和记录会一起回滚，可保留源文件再次处理。
查询模式只读取当前数据库，不会补采或删除来源数据。需要长期保留证据时，请备份整个数据库。
本地响应服务支持状态码、响应头、文本或 base64 字节正文；未配置路径返回未找到。
每条路径的脚本独立推进，最后一个响应会重复；可借请求记录核对调用顺序。
数据文件的路径均相对项目根目录，修改工作目录前请确认输入和数据库参数。

## 归并运维

人工决定先查询 `GET /candidates` 或 `GET /entities` 拿到各实体当前版本，再带版本提交 `POST /decisions`；
返回 409 说明自动更新已先行改变实体，按响应中的当前版本重新评估后再提交，不要强行重放旧决定。
拆分是对误合并的撤销：被拆实体退役但永不删除，其资源号不再分配给任何设备；
成员获得新资源号，历史引用可经 `GET /records/{键}/history` 与 `GET /entities/{资源号}/events` 解释。
携带 `observed` 的记录只接受更新的观察，更旧的快照被拦截并计入导入结果的 `skipped`，原文不丢失。
每次写入后可用 `GET /integrity` 校验：每条采集记录恰好映射到一个活跃实体。
